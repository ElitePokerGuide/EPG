# EPG Social Content Engine: стратегия запуска

**Версия:** 0.1 (черновик для обсуждения)
**Дата:** 2026-10-04
**Контекст:** Elite Poker Guide (elitepokerguide.io) владеет транскрибациями 1000+ покерных курсов от 40+ школ. Задача: превратить эти знания в автономную контент-машину (Instagram, TikTok, затем YouTube и другие), которая растит аудиторию на обучающем контенте и в итоге монетизируется до миллионов евро. Курсы напрямую в постах не продаём.

---

## 0. Главные выводы (TL;DR)

1. **Актив не в постинге, а в знаниях.** Транскрибации 40+ школ дают то, чего нет ни у одного покерного блогера: кросс-школьный консенсус по каждой теме. Это и есть продукт. Соцсети только дистрибуция.
2. **Миллионы евро приносит не органика, а продукт на рекуррентной подписке + воронка в EPG.** Выплаты платформ за просмотры в покерной нише слабые (TikTok/YouTube ограничивают гемблинг-тематику). Контент-машина должна быть спроектирована как воронка в собственные продукты с первого дня.
3. **Два главных риска надо закрыть до первого поста:** (а) авторские права школ на исходные курсы, (б) политика платформ по гемблингу и по неоригинальному / массовому AI-контенту. Оба решаются архитектурно (см. раздел 6), а не "потом".
4. **Стартуем узко:** один язык (EN), одна пара каналов (Instagram + TikTok), 5 форматов, 2 поста в день, ручная модерация через Telegram-бота первые 4-6 недель. Потом масштабируем на YouTube, вторые языки и сеть нишевых аккаунтов.
5. **Стек:** GitHub-репозиторий как источник правды → Claude Code / Agent SDK как "мозг" → RAG-база знаний → генерация скриптов → рендер видео (ffmpeg + Remotion + ElevenLabs) → Postiz (self-hosted) как единая публикация и аналитика → цикл обратной связи по метрикам.

## 2. Анализ вариантов

### 2.1 Форматы контента

| Вариант | Что это | Плюсы | Минусы | Вердикт |
|---|---|---|---|---|
| **A. Faceless short-form** (Reels / TikTok / Shorts) | AI-озвучка + анимация покерного стола + субтитры, 30-60 сек | Полная автоматизация; масштабируется на языки; алгоритмический охват | Высокая конкуренция; платформы давят "низкокачественный AI"; слабая лояльность | **Ядро на старте.** Качество визуала решает всё |
| **B. AI-аватар / клон ведущего** (HeyGen, Synthesia, свой голос) | "Говорящая голова" с синтезированным видео | Выше доверие и удержание чем у faceless | Дороже; риск "зловещей долины"; нужен реальный человек-лицо для клона | Тест на Фазе 2, если faceless упирается в потолок удержания |
| **C. Карусели / текст** (IG carousel, Threads, X, Telegram) | 7-10 слайдов "разбор концепта" или "ошибка → фикс" | Самый дешёвый рендер (HTML → PNG); IG-карусели дают лучший save-rate; идеально для теории | Меньше охват чем у видео | **Ядро на старте** вместе с A. 1 карусель в день |
| **D. Long-form YouTube** (8-15 мин) | Разбор темы с 3-5 школ: "что говорят Upswing, RIO и ... про 3-bet pot OOP" | Лучшая монетизация (AdSense, партнёрки в описании); SEO-долгоживущий трафик; авторитет | Дороже в производстве; ошибки в теории заметнее | Фаза 2. Собирается из уже сделанных шортсов + углублённый скрипт |
| **E. Интерактив** ("Что бы ты сделал?", квизы, опросы) | Ситуация → 3 варианта → ответ в комментах / следующем посте | Комментарии = сигнал алгоритму; данные о слабых местах аудитории | Нужна модерация | **Ядро на старте**, 1 из 5 форматов |
| **F. Длинные тексты / newsletter** | Еженедельный дайджест концептов + "курс недели" | Собственная аудитория вне алгоритмов; прямая монетизация | Медленный рост | Фаза 2, как цель воронки (email capture) |
| **G. Live / стримы** | Стрим с разбором рук | Доверие | Не автоматизируется | Не в фокусе |

### 2.2 Структура каналов

| Вариант | Описание | Когда |
|---|---|---|
| **Один бренд EPG** на всех платформах | Простая, узнаваемая | Фаза 1. Главный аккаунт |
| **Сеть нишевых аккаунтов** (MTT, Cash 6-max, PLO, Mental Game, Live Poker) | Каждый аккаунт с своим персонажем и углом; один движок | Фаза 3. После того как поняли, какие темы летят |
| **Языковые клоны** (RU, DE, ES, PT-BR) | Тот же контент, другой язык и TTS | Фаза 2-3. У EPG уже 5 языковых секций в каталоге, это готовая сегментация |
| **Персонажи-аватары** ("Coach Max", "GTO Nerd") | Выдуманные ведущие с устойчивым голосом и стилем | Подходит к B и к сети аккаунтов |

Ключевое правило сети: **никогда не постить один и тот же ролик на несколько своих аккаунтов.** Meta с 2025 активно режет "неоригинальный контент", TikTok так же. Один концепт → разные скрипты, хуки, визуал.

### 2.3 Степень автономности

| Режим | Описание | Когда |
|---|---|---|
| **Human-in-the-loop** | Бот в Telegram присылает готовый пост (видео + подпись) → ✅ / ❌ / ✏️ | Недели 1-6. Учим машину вкусу и ловим ошибки в теории |
| **Auto-publish с выборочным ревью** | Публикует сам, 10-20% постов на ревью, стоп-слова и правила качества автоматом | Недели 6-12 |
| **Полная автономия + недельный отчёт** | Человек смотрит только метрики и правит стратегию | С 3-го месяца, только на проверенных форматах |

### 2.4 Инструменты публикации

| Вариант | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| **Postiz (self-hosted, open source)** | 28+ платформ, CLI + API + MCP, уже установлен как плагин в нашем Claude-окружении, аналитика по постам, DIRECT_POST для TikTok | Нужен VPS и настройка OAuth-приложений Meta/TikTok/Google | **Выбор.** Один интерфейс для всего |
| Прямые API (Meta Graph, TikTok Content Posting, YouTube Data) | Нет посредника | Три разных интеграции, у TikTok API-аудит приложения, долго | Фолбэк, если Postiz не потянет что-то специфическое |
| Buffer / Later / Metricool (SaaS) | Быстро | Платно за аккаунт, слабые API, нет контроля | Нет |
| Неофициальная автоматизация (браузерные боты, "warm-up фермы") | Обходят лимиты | Прямая дорога к бану, особенно на TikTok | **Никогда.** Один бан главного аккаунта стоит дороже всей экономии |

## 3. Монетизация: как дойти до миллионов

### 3.1 Честная математика

Цель "миллионы евро" переведём в число: **3 млн € / год = 250 тыс. € / мес.** Органика в соцсетях сама по себе так не зарабатывает. Она даёт трафик, который надо конвертировать в продукт с высоким LTV.

| Источник | Единица | Нужно для 250k€/мес | Реалистичность |
|---|---|---|---|
| Продажи каталога EPG (средний чек ~50-80 €) | заказ | ~3 500-5 000 заказов/мес | Высокая при аудитории 500k+ и email-базе 100k+. Это основной канал Фаз 1-2 |
| Подписка "EPG AI Poker Coach" (29-49 €/мес) | подписчик | ~6 000-8 500 активных | Это главный рычаг. Churn в обучении 5-8%/мес, нужен постоянный приток ~500-700 новых/мес |
| Партнёрки покерного софта (GTO Wizard, PioSolver, Hand2Note, DTO) | рефералы 20-30% | дополнение, +10-20k€/мес | Безопасно по политикам платформ |
| Партнёрки покер-румов (CPA 100-300 € / rakeback) | игрок | очень доходно, но | **Риск:** TikTok запрещает гемблинг-промо почти везде, Meta требует лицензии. Только через собственный сайт / email / Telegram, не в постах |
| Выплаты платформ (YT Partner, TikTok Rewards, IG Bonuses) | просмотры | +5-20k€/мес | Бонус, не план. Гемблинг-смежность снижает RPM |
| Спонсорство (румы, софт, трекеры) | контракт | 5-30k€/мес на аккаунт при 200k+ | Фаза 3 |
| **SaaS "контент-движок для образовательных ниш"** | B2B-клиент 500-5000 €/мес | 50-500 клиентов | Фаза 4. То, что мы построим, не привязано к покеру |

**Вывод:** путь к 3M€ = EPG-каталог (~40%) + подписочный продукт (~40%) + партнёрки/спонсоры/SaaS (~20%). Реалистичный горизонт: 18-36 месяцев при дисциплинированном исполнении. Любой план "органика → миллионы за полгода" это самообман.

### 3.2 Воронка (без прямой продажи курсов в постах)

```
Пост (Reel / carousel / Short)
  → хук на знание, не на продажу
  → CTA: "полный разбор в закрепе / по ссылке в био"
      → Lead magnet: бесплатный PDF/мини-курс "7 ошибок ... от 5 школ" (email + Telegram)
          → Автосерия писем/сообщений (7-14 дней): ценность → ценность → мягкое предложение
              → EPG каталог (скидка подписчикам) и/или AI Coach (trial 7 дней)
                  → Удержание: еженедельный дайджест, челленджи, комьюнити
```

Соцсети продают знание. Продажа курсов живёт на своём домене, в email и Telegram. Это и соответствует запросу "не постим курсы напрямую", и снимает большую часть платформенных рисков.

### 3.3 Продукт, которого ещё нет и который стоит построить: "EPG AI Coach"

Та же база знаний (слой 1), что питает контент, может питать и чат-тренера: игрок задаёт ситуацию, получает ответ с позициями разных школ, тренировочные дриллы, квизы, план обучения. Это:
- рекуррентная выручка;
- причина для подписчика остаться (а не купить один курс и уйти);
- бесконечный источник контент-идей (реальные вопросы пользователей → посты).

Строится на той же RAG-инфраструктуре, стоимость дополнительной разработки умеренная. Рекомендую заложить в Фазу 3.

## 4. Архитектура системы

### 4.1 Слой 1: База знаний

Это единственная невоспроизводимая часть. Делаем аккуратно.

```
knowledge/
  raw/                      # транскрибации как есть (не коммитим в публичный репо!)
    <school>/<course>/<lesson>.txt|.srt|.json
  normalized/               # очищенный текст + метаданные (JSONL)
  taxonomy.yaml             # формат (MTT/Cash/PLO/SNG/HU/Live), стек, тема, концепт, уровень
  concepts/                 # атомарные "концепт-карточки" (см. ниже)
  index/                    # эмбеддинги (локально или в pgvector / Qdrant / LanceDB)
```

**Концепт-карточка** это атомарная единица знания, извлечённая из транскрибации:

```yaml
id: c-3bet-oop-cbet-freq-001
topic: "C-bet frequency OOP in 3-bet pots"
format: cash-6max
level: intermediate
claim: "OOP как 3-беттор в SRP-текстурах с низкими картами чаще чекает, чем бетит..."
why: "..."
example_hand: { hero: "AKo", board: "7s5d2c", action: "..." }   # для реплеера
source_refs: [ {school: "...", course: "...", lesson: "...", ts: "12:40-14:10"} ]  # внутренняя ссылка, НЕ публикуется
consensus_score: 0.85          # сколько школ согласны
contradictions: [ "Школа X рекомендует range-bet мелко ... " ]
```

Почему это важно:
- **Юридически:** мы публикуем идеи и наше собственное объяснение, а не текст курса. Покерная теория (GTO, диапазоны, частоты) не защищается авторским правом, конкретный текст и видео курса защищаются. Карточка разрывает связь с оригинальным текстом.
- **Качество:** `consensus_score` даёт уверенность. Конфликты школ это отдельный золотой формат контента ("Школа A vs Школа B: кто прав про ...").
- **Масштаб:** 1000 курсов → десятки тысяч карточек → годы контента без повторов.

Пайплайн: `ingest → clean → chunk → extract concepts (Claude) → dedupe/merge → score consensus → embed`. Запускается как Routine (cron) при каждом пополнении `raw/`.

### 4.2 Слой 2: Производство

```
content/
  formats/                  # шаблоны форматов (ниже)
  hooks.yaml                # библиотека хуков с рейтингами (обновляется по метрикам)
  voice.md                  # голос бренда: как объясняем, чего не говорим, тон
  queue/                    # сгенерированные посты: script.md + assets/ + meta.json
  published/                # архив с метриками
```

**Стартовые 5 форматов** (все из одной карточки, разные углы):

| # | Формат | Длина | Хук-паттерн |
|---|---|---|---|
| 1 | "Ошибка → почему → фикс" | Reel 30-45 с | "99% игроков на 20NL делают это в 3-bet потах..." |
| 2 | "Что бы ты сделал?" | Reel 20-30 с + ответ в комментах/следующем | Стоп-кадр руки, 3 кнопки, "ответ завтра" |
| 3 | "5 школ, 1 вопрос" | Карусель 8-10 слайдов | "Мы прочли 5 курсов про X. Вот где они расходятся" |
| 4 | "Концепт за 60 секунд" | Reel 55-60 с | "Поляризация объяснена без математики" |
| 5 | "Миф vs факт" | Reel 30 с или карусель | "'Всегда c-bet в позиции' это ложь, и вот почему" |

**Рендер видео (без оператора, без лица):**
- **Скрипт:** Claude генерирует из карточки: хук (первые 1.5 сек!), тело, CTA, подпись, хэштеги, обложку. Строгие правила: без имён школ/тренеров, без цитат длиннее 8 слов, с проверкой фактов против карточки.
- **Озвучка:** ElevenLabs (устойчивый голос бренда на каждый язык). Альтернатива дешевле: OpenAI TTS / Azure.
- **Визуал:** собственный **ханд-реплеер** (hand history → анимация стола в стиле EPG), генерируется Remotion (React) или Python + ffmpeg. Плюс анимированные диапазоны (13×13 грид), текстовые карточки, b-roll из лицензионного стока. Это главный рычаг качества и оригинальности.
- **Субтитры:** word-level (Whisper / ElevenLabs alignment), стиль "караоке" как у топовых шортс.
- **Карусели/обложки:** HTML-шаблон → Playwright screenshot → PNG. Дёшево, брендировано, повторяемо.
- **QA автомат:** длительность, громкость, запрещённые слова, упоминание школ, читаемость субтитров, затем превью в Telegram на approve.

### 4.3 Слой 3: Дистрибуция

- **Postiz self-hosted** на VPS (Hetzner/Contabo, ~20-40 €/мес). Подключаем IG (через Facebook Page + Business account), TikTok (DIRECT_POST), YouTube, Threads, X, Telegram.
- Правила: `postiz upload` для каждого медиа, `integrations:settings` перед каждым постом (у TikTok и IG обязательные поля), расписание по тайм-зонам целевой аудитории (EN: 12:00 и 19:00 ET; RU: 19:00 MSK).
- **Каденс старта:** IG 1 Reel + 1 карусель/день, TikTok 2 Reel/день (можно те же ролики, что в IG, кросс-платформенно это ок, не ок внутри одной платформы), Stories 2-3/день из нарезок. Каждый пост уникален по тексту/хуку.
- **Аналитика:** `postiz analytics:post` через 24ч / 72ч / 7д → в `published/*/metrics.json` → недельный скоринг хуков, тем, форматов, времени → обновление весов в `hooks.yaml` и выборе тем (простой multi-armed bandit: 70% проверенного, 30% экспериментов).

### 4.4 Слой 4: Оркестрация

- **Источник правды:** этот GitHub-репозиторий. Всё, что сгенерировано, коммитится (кроме `knowledge/raw/`, он в приватном хранилище: приватный репо / S3 / Google Drive с синком).
- **Мозг:** Claude Code с Routines (scheduled triggers) или Claude Agent SDK на VPS / GitHub Actions:
  - `ingest` при пополнении транскрибаций;
  - `plan-week` каждое воскресенье: 14-20 постов на неделю по весам;
  - `produce` ежедневно: рендер завтрашних постов → Telegram на approve;
  - `publish` по расписанию через Postiz;
  - `measure` ежедневно: метрики → скоринг;
  - `report` еженедельно: краткий отчёт + предложения по стратегии.
- **Human-in-the-loop:** Telegram-бот с кнопками Approve / Reject / Edit; в Reject записывается причина, она попадает в промпты как негативный пример.

### 4.5 Предлагаемая структура репозитория

```
EPG/
  docs/strategy/            # этот документ, решения, пост-мортемы
  knowledge/                # слой 1 (raw в .gitignore)
  content/                  # слой 2
  pipeline/
    ingest/                 # транскрибации → карточки → индекс
    generate/               # карточка → скрипт → подпись
    render/                 # TTS, реплеер, субтитры, ffmpeg/Remotion
    publish/                # обёртка над Postiz CLI
    measure/                # сбор метрик, скоринг
    review/                 # Telegram-бот модерации
  .claude/
    skills/                 # навыки: /plan-week, /produce, /publish, /report
    settings.json
  infra/                    # docker-compose для Postiz, VPS-скрипты
```

## 5. Дорожная карта

### Фаза 0: Фундамент (недели 1-2)

- [ ] Решения по открытым вопросам (раздел 8).
- [ ] Залить первые транскрибации (10-20 курсов по 1 формату, например Cash 6-max) в приватное хранилище; настроить синк.
- [ ] Ingest-пайплайн: карточки + таксономия + индекс. Критерий: 500+ карточек, ручная проверка 50 случайных на точность.
- [ ] `voice.md` и юридические правила генерации (раздел 6).

- [ ] Postiz на VPS, подключение аккаунтов, тестовый пост на каждом.

**KPI фазы:** пайплайн работает end-to-end, стоимость 1 поста ≤ 2 €, 0 юридических нарушений в 30 постах.

### Фаза 1: Один язык, одна пара каналов (недели 3-8)

- EN, Instagram + TikTok, 5 форматов, 2-3 поста/день, human-in-the-loop.
- Еженедельно: отчёт, отключение худшего формата, добавление одного нового.
- Lead magnet + лендинг (email + Telegram), ссылка в био. Отслеживаем переходы (UTM) и подписки.
- **KPI к концу (ориентир, без гарантий):** 10-25k подписчиков суммарно, ≥3 ролика >100k просмотров, 1-2k email/Telegram-подписчиков, понимание 2-3 "летающих" форматов, стоимость поста ≤ 1 €.

### Фаза 2: YouTube, второй язык, воронка (месяцы 3-4)

- YouTube Shorts (репост с адаптацией) + 1-2 long-form в неделю, собранные из карточек с высоким консенсусом.
- Второй язык: RU или DE (у EPG готовые языковые секции каталога). Отдельные аккаунты.
- Email-автосерия → EPG каталог с трекингом выручки по UTM. Партнёрки софта.
- Переход на auto-publish с выборочным ревью.
- **KPI:** 100k+ суммарно, 10k+ email/TG, первая атрибутируемая выручка EPG из соцсетей (цель 5-15k €/мес), YouTube монетизация включена.

### Фаза 3: Сеть и продукт (месяцы 5-9)

- Сеть нишевых аккаунтов (MTT / Cash / PLO / Mental), каждый со своим персонажем.
- Запуск **EPG AI Coach** (подписка) на той же базе знаний. Контент начинает вести в него.
- Спонсорские пакеты, партнёрки румов только через собственные каналы (сайт, email, Telegram).
- Полная автономия с недельным отчётом.
- **KPI:** 500k+ суммарно, 1-2k подписчиков AI Coach, 50-100k €/мес совокупно.

### Фаза 4: Масштаб (месяцы 9-18)

- Платная реклама на проверенных креативах (которые уже доказали себя органически) → масштабирование воронки.
- 4-5 языков.
- Упаковка движка как SaaS для других образовательных ниш (шахматы, трейдинг, языки): одна команда, N ниш.
- Команда: 1 продюсер-редактор (вкус и факты), 1 инженер, 1 комьюнити/саппорт.
- **Цель:** траектория к 250k €/мес.

## 6. Риски и как их закрываем

| Риск | Серьёзность | Митигация |
|---|---|---|
| **Авторские права школ.** Транскрибации это защищённый контент. Публикация фрагментов, видео, слайдов или узнаваемых структур уроков = DMCA, иски, репутация | Критический | Публикуем только концепт-карточки в своей формулировке; запрет цитат >8 слов; никаких имён школ/тренеров/курсов в контенте; никакого аудио/видео из курсов; собственный визуал. Автопроверка на n-gram совпадения с исходником. Юрконсультация в Фазе 0 (EU-юрисдикция). Контент-фильтр как часть QA |
| **Гемблинг-политики платформ.** TikTok запрещает промо гемблинга почти глобально, Meta требует лицензии на рекламу, YouTube ограничивает монетизацию | Высокий | Контент = обучение стратегии (разрешено, десятки крупных покерных каналов живут так). Никаких ссылок на румы, бонусов, "депозит" в постах. Партнёрки румов только за пределами платформ. Возрастная маркировка 18+ |
| **Неоригинальный / массовый AI-контент.** Meta и TikTok с 2025 понижают охват повторов и "спам-аккаунтов" | Высокий | Один концепт = разные скрипты на разных аккаунтах; собственный реплеер и графика; живая озвучка (не роботизированная); лимит постов/день; реальные ответы на комментарии |
| **Бан за автоматизацию** | Высокий | Только официальные API через Postiz. Без браузерных ботов. Прогрев аккаунтов ручными постами. Диверсификация: минимум 2 платформы и собственная email/TG-база с первого месяца |
| **Ошибки в теории** (галлюцинации, устаревшие советы) | Средний | Генерация только из карточек с источником; consensus_score ≥ 0.6 для автопубликации; ревью человека первые 6 недель; формат "школы расходятся" честно показывает неопределённость |
| **Контент не летит** | Средний | Быстрые итерации: 5 форматов, недельный цикл отключения худшего. Библиотека хуков учится на метриках. Готовность сменить персонажа/подачу, а не тему |
| **Зависимость от одного человека-владельца** | Средний | Все решения, промпты и правила в репо; Routines работают без ручного запуска |
| **Платформа меняет правила / API** | Средний | Postiz как абстракция; owned-аудитория (email, TG) как страховка |

## Приложение A. Почему это сработает именно у EPG

- У отдельного тренера одна точка зрения. У EPG 40+ школ, и "где они согласны / где расходятся" это контент, который никто другой физически не может произвести.
- Каталог уже существует: воронке есть куда вести с первого дня.
- 5 языковых секций каталога = готовая карта локализации.
- Движок знаний переиспользуется в подписочный продукт и в B2B-SaaS, то есть один раз построенная инфраструктура работает на три бизнес-модели.

## Приложение B. Чего не делаем

- Не постим фрагменты курсов, слайды, аудио, видео, имена школ и тренеров.
- Не используем неофициальную автоматизацию и "фермы" аккаунтов.
- Не рекламируем румы, бонусы, депозиты в постах на платформах.
- Не публикуем один ролик на несколько своих аккаунтов одной платформы.
- Не обещаем "миллионы за полгода": план на 18-36 месяцев с чекпоинтами, где каждая фаза должна доказать цифры перед следующей.
